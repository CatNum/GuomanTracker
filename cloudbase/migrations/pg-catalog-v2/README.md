# PG 目录统一迁移

## 重点

- **增量变更**：新增节目分页、规范链接查询与批量资料写入函数，
  复用已有私有文档表和提交锁，不清空或替换原有存储。
- **数据保护**：初次导入只补齐缺失节目；显式更新仅接受较新核验时间。
  旧链接规范化使用完整原文档读集，冲突或结果未知时停止。
- **应用入口**：公开目录函数只读节目白名单字段；个人函数继续要求正式账号。
  页面加载只读 PG，不请求官方日历，也不使用文件目录回退。

## 一、执行顺序

执行前核对目标环境、数据库和后端角色，并私下保存原记录与函数代码。
不能把用户数据、凭证或备份文件提交到仓库。

1. 在既有 PG 环境执行 `001-catalog.sql`（增量目录 SQL）。
   文件在函数已存在时主动失败，异常后先核对对象，不能盲目重复执行。
2. 准备一次性迁移输入，并预览导入；输入来源于迁移前保留的目录副本，
   应用、网页构建和云函数运行均不会读取该输入。
3. 显式执行导入；先将旧 PG 节目链接规范化，再补齐缺失节目。
   保留节目标识、个人进度、优先级、配额及已有节目其他资料。
4. 执行 `verify.sql`（真实 PG 回滚验证），检查插入、重复导入、
   新旧资料更新、规范链接查询、分页和 SQL 权限，并回滚全部探针数据。
5. 比对所有旧记录及全部导入节目标识；先验证新公开目录函数，再切换个人函数及网页。

迁移工具从管理员已登录的 CloudBase CLI 获取访问能力，不读取或输出管理凭证。
在仓库根目录执行，以下输入路径和环境需替换为已核对的实际值：

```sh
node cloudbase/scripts/import-pg-catalog.mjs --input=/private/path/catalog-backup.json
node cloudbase/scripts/import-pg-catalog.mjs --input=/private/path/catalog-backup.json \
  --env=VERIFIED_ENV_ID --apply
```

工具默认预览；`--apply`（执行导入）才写入。
当前工具限定既有、已核验的项目环境，不接受任意环境迁移。
每批最多 100 条；任何未确认结果都会停止，需先只读核对数据库再继续。

## 二、公开目录授权

PG 环境使用 OPA 授权，`function-rules.json`（函数权限模板）不会自动生效。
当前游客请求到达目录函数前被网关以 403 拒绝，管理端函数调用已确认 PG 查询成功。
待授权的 [目录访问策略](../../catalog-access.rego) 仅匹配本环境的
`POST /v1/functions/guoman-catalog`（公开目录调用路径），未设置全局默认或拒绝规则。

根据 [CloudBase OPA 决策矩阵](https://docs.cloudbase.net/envconfig/authz-opa/intro)，
用户允许规则未命中时沿用平台默认策略；
[策略管理说明](https://docs.cloudbase.net/en/cli-v1/policy/management)
也明确指出保存用户策略后旧网关鉴权会失效。
因此必须核对并备份既有策略，明确授权后应用，
再用真实游客会话检查目录读取和个人入口拒绝，不能仅靠模板宣称已开放。

本轮两次策略写入被自动审批拒绝，均未执行，当前等待用户单独授权。
公开目录验证通过前，不切换线上网页或个人函数。

## 三、后续资料写入

用户补录通过认证用户函数确认官方标题并事务保存。
受信管理员可向同一迁移工具提供已核验的节目资料，
加 `--update`（允许更新较新资料）和 `--apply` 写入 PG。
不带更新参数时，重复导入不会覆盖已有节目。

这条管理员资料写入路径不等于自动抓取；
按官方排期提前进入高频抓取窗口的调度机制仅记录在产品 Roadmap。
旧文档库扫描入口本轮不部署，页面也没有手动触发抓取入口。

## 四、恢复原则

优先恢复此前保存的用户函数和静态页面代码，保留新增 PG 节目与函数。
本次迁移不删除旧数据，恢复旧应用无需清空表或回滚个人记录。
新目录函数可以保留为只读入口；如需停用，单独停用该入口，
不得放宽个人函数权限或数据库角色权限来处理故障。
