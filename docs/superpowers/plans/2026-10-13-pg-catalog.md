# PG 目录统一实施计划

## 重点

- **已确认范围**：PG 唯一目录来源，游客只读，补录和更新持久化；
  去除 JSON 目录及手动同步，自动抓取仅记录 Roadmap。
- **数据保护**：保留原节目标识和全部用户记录；导入不覆盖已有较新资料。
- **验证边界**：先测试、双构建和审查，再执行非破坏迁移与发布；
  真实环境结果单独记录，不以替身测试代替。

> 执行方式：本会话内逐项实施，使用 executing-plans 与 test-driven-development；
> 最后独立审查。用户已逐项确认完整范围，不重复请求实施授权。

**Goal（目标）**：目录和个人节目资料统一使用 PG，刷新只读，去除文件回退。

**Architecture（架构）**：复用私有 JSONB 文档表和现有事务协议，
新增固定的目录分页与规范链接查询 SQL 函数。
独立公开目录云函数仅允许目录读取，用户函数继续强制认证。
静态网页在运行时读取目录，不在构建时打包节目数据。

**Tech Stack（技术栈）**：现有 Next.js、React、CloudBase SDK、PG、Node 测试。

**Spec（需求依据）**：本聊天 Q1 至 Q5 的确认，以及产品 Roadmap 的本轮范围。

## 一、全局约束

- 不改变已有账号记录、节目标识或进度，不清空表，不部署自动扫描任务。
- 不修改旧文档；新增计划、Roadmap 和迁移说明记录本轮事实。
- 公共目录只返回节目白名单字段，不暴露提交者或个人数据。
- 数据库故障不返回 JSON 回退；未确认提交不自动重放。
- 使用现有依赖，不新增外部数据服务，不启用付费服务。

## 三、重点审查

- 公开目录不能通过载荷访问个人集合或调用写动作。
- 导入不得用旧快照覆盖较新 PG 记录，也不能改变已有追番所引用的编号。
- 大目录必须有界读取，游标不能死循环或静默截断。
- 官网读取不能混入游客页面加载链路，后台规划本轮不启用。
- 数据库故障与提交结果未知必须明确报告，不能显示空库成功或保存成功。
