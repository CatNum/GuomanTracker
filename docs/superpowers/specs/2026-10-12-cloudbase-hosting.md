# CloudBase 既有域名部署方案

## 重点

- **目标**：将最新追番页面部署到既有 CloudBase 白名单域名，
  完成真实邮箱登录、记录恢复及目录同步验收。
- **复用后台**：保留账号、PG、用户云函数权限及现有数据。
  不新增匿名访问，不部署尚未接入 PG 的扫描函数。
- **双构建**：普通 Next.js 构建保留；另行生成静态托管产物。
  CloudBase 游客浏览收录快照，登录后自动同步官方日历。
- **发布边界**：复用已开通的托管，不购买或升级套餐，
  保留既有认证和管理页面；新资源先上传，首页最后上传。

## 一、问题与范围

EdgeOne 默认域名仅提供带校验参数的三小时预览，且其网页来源被
CloudBase 实际认证网关拒绝，跨域预检返回 403。
既有 `tcloudbaseapp.com` 域名的同一预检返回 204，
但当前根路径返回 404。静态托管已在线，默认首页为 `index.html`。

当前前端包含一个动态目录接口，不能原样作为纯静态文件发布。
邮箱登录、账号记录及进度均通过现有用户云函数访问，
因此前端迁移不涉及账号或数据库迁移。

## 二、架构

新增 `cloudbase/shared/catalog-service.mjs`（官方目录读取服务），
注入快照、网络读取器及时间，返回 `{ items, live }`：
`items`（作品数组）沿用现有目录字段，
`live`（本次是否成功读取官方日历）准确区分实时数据与回退快照。
普通 Next.js 的 `/api/catalog`（目录接口）与用户云函数共用此服务。

现有用户云函数增加 `getCatalog`（只读目录动作）。
可信非匿名身份验证必须先执行；目录分支在构造 PG 客户端之前返回，
不读写数据库，不读取账号资料，不接受自定义 URL。
请求只接受空业务参数，返回既有 `{ ok: true, data }` 结构。

CloudBase 静态模式通过 SDK 调用该动作。游客继续浏览快照，
点击同步时明确引导邮箱登录；登录成功后自动同步。
普通 Next.js 模式继续允许游客自动或手动读取现有公开目录接口。
组件卸载、退出或账号变化后忽略旧请求的迟到结果。

## 三、构建与安全边界

新增 `build:cloudbase`（静态托管构建命令），在临时源码副本中
排除动态目录路由并启用静态导出，不删除、改名或恢复原源码文件。
共享模块相对路径保持一致；构建产物输出到忽略目录。
公开构建配置从当前进程传入，不把凭证、私密环境文件、Git 历史
或云函数管理凭证复制进静态产物。

官方目录只读取固定 B 站 HTTPS 接口，限制十秒超时、响应体字节数
和条目数，验证结构、数值、字符串及官方封面域名。
成功结果按实例缓存十分钟，并合并并发请求；失败回退三平台快照，
清理进行中的请求，允许后续重试。

不更改身份源、云函数调用权限、安全域名和数据库结构。
不启用扫描器、定时任务或付费日志，不购买或升级服务。

## 四、验证与发布

先验证目录合并、非法响应、超时、体积限制、缓存、并发和失败重试；
验证匿名及伪造身份不能调用目录动作，正式账号读取目录不构造 PG。
运行单元测试、类型检查、lint、普通构建与静态构建。
静态首页、资源、404 和微信兼容回调页均应存在。

保留远端函数状态及旧代码包，先更新向后兼容的用户云函数，
确认正常运行，再发布静态前端。使用安全上传及远端校验，
不清空或清理远端目录，产物不得包含 `__auth`（认证系统目录）
或 `cloud-admin`（管理页面目录）。既有六个系统文件必须保留。

在 CloudBase 新地址用真实邮箱验收验证码、登录、原记录恢复、
目录同步以及刷新后的会话与记录保留。用户输入验证码，
不复制本地令牌到新来源，不通过替代会话宣称登录成功。
目录上游失败应明确显示回退，不把回退当成实时同步成功。

## 五、回滚与限制

后端新增动作向后兼容，优先回滚前端；必要时恢复已保存的旧用户函数。
首次发布前 CloudBase 根路径没有可用旧站，因此撤回首页只能恢复原先
404 状态，不能宣称恢复到可用旧前端。既有 EdgeOne 部署继续保留。

默认 CloudBase 域名适用于开发测试，可能展示访问提示页；
正式长期使用仍需稳定域名。方案参考
[静态托管部署指南](https://docs.cloudbase.net/hosting/web-hosting-guide)
与 [默认域名说明](https://docs.cloudbase.net/service/alias)。
