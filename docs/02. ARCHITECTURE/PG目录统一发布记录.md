## 一、源码与本地验证

工作分支为 `codex/pg-catalog`，基于提交 `9a2f769`。
本轮不修改旧架构、部署和验收文档，新增 Roadmap、计划与本记录说明变化。

- 页面运行时读取公开 PG 目录，游客不创建匿名账号。
- 公开目录函数只允许分页读取，返回节目白名单字段，不返回用户或提交者。
- 个人函数继续从可信调用上下文取身份，节目资料不再依赖文件快照。
- 补录复用数据库节目标识，已有个人进度、顺序及配额规则保留。
- 一次性导入默认只新增缺失节目；较新资料更新须显式选择更新模式。
- 页面不再提供手动官网同步，读取失败提示重试，保留本页已加载内容。
- 删除旧文件采集脚本和依赖文件目录的管理员热门种子入口。
  新自动采集与调度只进入 Roadmap，当前不启用旧文档库扫描器。

类型检查与本轮修改文件的 ESLint 检查通过。

新增写入复用原提交锁，仅后台角色可执行；客户端不直接获得 SQL 权限。

## 三、云端发布与阻碍

`guoman-catalog`（公开目录云函数）已经部署并读回 Active，
管理端真实调用返回成功，每页 200 条，游标正常。
这证明云端函数能够访问 PG，但不能代替浏览器游客授权验收。

独立未登录浏览器已经验证：目录读取失败时展示错误与重试入口，
没有退回 JSON 目录，也没有刷新日历或同步按钮。
实际请求跨域预检为 204，目录 POST 返回 403，阻碍位于 CloudBase 网关授权层。

当前环境的用户与扩展自定义 OPA 策略都读回为空。
拟应用 [目录访问策略](../../cloudbase/catalog-access.rego)，
只允许现有环境的公开目录固定 POST 路径，其余资源沿用平台默认规则。
两次写入被自动审批拒绝，理由是环境级持久安全变更需要明确授权；
两次操作均未执行。已向用户请求单独授权，尚未获得答复。

公开游客读取通过前，不切换个人函数与线上静态网页。
当前正式站点仍运行旧版本，不能把已迁移数据库说成网页已完成切换。

## 四、继续发布的检查项

1. 用户明确授权后应用目录策略，读回比对实际策略与仓库文件。
2. 全新游客会话读取 PG 全目录，确认未创建匿名账号。
3. 公开目录拒绝写动作；个人函数拒绝无身份与仅可发布密钥的请求。
4. 更新已备份的个人函数，保留原配置及身份门禁。
5. 使用安全上传与远端校验发布静态页面，保留系统文件及旧资源。
6. 在正式域名检查目录、筛选、周历、错误提示和移除同步后的页面布局。
7. 记录真实账号验收边界；没有执行的登录或写入验证不能宣称通过。
