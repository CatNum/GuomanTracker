# GuomanTracker 产品 Roadmap

## 重点

- **统一节目数据来源**：节目目录、补录与资料更新统一持久化到 PG，
  游客和登录用户均读取数据库目录，移除目录 JSON 读取与回退逻辑。
- **取消手动同步**：本轮移除刷新日历、同步日历等入口；
  页面加载和刷新只读取数据库，不由用户触发官网抓取。
- **核心扩展功能**：按排期自动抓取，让官方更新消息尽快传递到网站，
  并结合最新剧集的“第一时间看”按钮与排行榜；暂时只记录规划，不实现。

## 一、本轮范围：统一存储与目录读取

状态：核心发布于 2026-10-16 完成。PG 数据迁移、公共目录 HTTP 读取、
个人函数和静态网页均已上线，正式域名游客当前读取 3,248 个节目成功。
真实账号补录已有节目、进度保存和刷新读取，以及正式筛选、周历、手机宽度验收已通过。
管理员依据官方资料更新 PG 后，正式浏览器刷新复读已通过。
腾讯元数据识别修复后，真实新节目补录、PG 保存与游客页面读取均通过，测试产生的个人状态已恢复。
优酷官网返回验证页或缺少可信标题时仍拒绝补录，
详见[发布记录第十节](../02.%20ARCHITECTURE/PG目录统一发布记录.md#十云端识别修复与新节目持久化验收2026-10-16)。

- 节目目录以 PG 为唯一数据来源，游客也读取 PG 公共目录。
  个人追番、进度和优先级继续要求登录，并按账号隔离。
- 补录和资料更新必须保存到 PG，不能只更新页面或服务内存。
  未取得持久化成功确认时，不提示保存成功。
- 去除目录 JSON 的读取、打包和回退逻辑。
- 移除刷新日历、同步日历等手动抓取入口。
  页面刷新仅重新读取数据库，不触发官网采集。
- 数据库不可用时，保留当前页面已经加载的内容并明确提示错误；
  首次加载失败则显示错误与重试入口，不使用内置 JSON 目录兜底。

## 二、核心扩展：更新及时传递与“第一时间看”排行榜

状态：设想记录，暂不实现，未安排发布日期。按 2026-10-17 的产品方向，
这属于核心扩展功能，不属于当前核心卡点功能。

### 2.1 用户目标

按排期自动抓取解决的是：**如何第一时间将官方剧集更新消息传递到网站**。
用户打开产品即可获取后台已核验并保存的节目更新，
无需例行点击同步或逐个平台确认是否上线。

追番用户会在动漫弹幕中发送“第一”“第一”等词语，表达自己是最先观看的一批人。
产品计划提供最新剧集的专属按钮与本期排行榜，承接这种参与感。

### 2.2 基于官方排期的计划扫描

1. 最开始抓取节目资料时，同时获取官方更新时间，例如每周六 11:00。
2. 在临近更新时间的前五分钟开始，有计划地扫描对应官方接口或网址。
   例如周六 11:00 更新，则从周六 10:55 开始；时间示例按北京时间理解。
3. 扫描采用固定间隔或小范围随机间隔，具体间隔暂未确定。
4. 官网确认更新后，将新剧集资料、核验结果与处理状态写入 PG，
   网站目录、周历与观看推荐读取同一份数据库资料。

排期时间已到不能直接视为剧集已发布，仍需校验官方实际更新结果。

### 2.3 最新剧集的专属按钮与本期排行

对最新更新的剧集提供一个特殊按钮，供用户表达自己是第一时间观看的，
并形成针对**本期剧集**的排行榜。按钮名称暂未确定，按以下两种情况处理：

| 网站状态 | 点击后的计划行为 |
| --- | --- |
| 网站尚未抓取到本期剧集更新 | 校验官方是否确已更新；若确认更新，该用户成为本期第一，后续用户依次排名 |
| 网站已记录本期剧集更新 | 直接跳转官方播放链接，并在本期排行榜中依次排名 |

第一种情况没有确认官方更新时，不授予本期排名；其后的具体提示、
是否跳转等交互留待设计。第一种情况确认更新后的播放跳转细节也待确定。

这里的用户点击校验是排行榜参与流程的一部分，
后台计划扫描仍负责主动发现更新，不恢复原来的刷新日历、同步日历入口。

### 2.4 点击次数与负载限制

该按钮需要限制使用次数，避免重复点击触发大量官方校验请求，
造成较高负载与并发压力。**次数暂定为 3 次**。

次数按用户、剧集还是时间周期计算，何时重置，
以及未更新、校验失败、已更新直接跳转等情况是否扣减次数，均尚未确定。
目前只记录次数限制方向，不将“3 次”解释为已经确定的每日或每集配额。

### 2.5 后续需要设计的内容

- **扫描规则**：具体间隔、随机范围、窗口持续时间、更新确认后的停止条件、
  延期与缺失排期处理、失败退避、平台限流与资源预算，
  以及现有扫描入口的 PG 存储接入。
- **排行规则**：排名的时间依据、同时点击的先后判定、重复参与处理、
  用户身份要求，以及“本期”的平台、节目和剧集划分。
- **观看含义**：按钮表达用户第一时间观看的参与意愿；
  当前尚未确定如何核实用户是否实际开始或完成观看，
  不将点击或官方链接跳转自动等同于观看事实。
- **请求控制**：3 次限制的统计与扣减口径、并发校验的合并复用、
  排名写入的去重与一致性规则，均留待功能启动时设计。

本次只更新产品规划，不新增扫描任务、用户按钮、排行榜或次数限制实现。
