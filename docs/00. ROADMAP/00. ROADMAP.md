# GuomanTracker 产品 Roadmap

## 重点

- **统一节目数据来源**：节目目录、补录与资料更新统一持久化到 PG，
  游客和登录用户均读取数据库目录，移除目录 JSON 读取与回退逻辑。
- **取消手动同步**：本轮移除刷新日历、同步日历等入口；
  页面加载和刷新只读取数据库，不由用户触发官网抓取。
- **自动追踪官方更新**：后续根据官方排期自动调整抓取频率，
  将确认结果写入 PG；本轮只记录规划，不实现该调度机制。

## 一、本轮范围：统一存储与目录读取

状态：进行中。PG 数据迁移已完成；公开目录授权与页面发布待完成。

- 节目目录以 PG 为唯一数据来源，游客也读取 PG 公共目录。
  个人追番、进度和优先级继续要求登录，并按账号隔离。
- 补录和资料更新必须保存到 PG，不能只更新页面或服务内存。
  未取得持久化成功确认时，不提示保存成功。
- 去除目录 JSON 的读取、打包和回退逻辑。
- 移除刷新日历、同步日历等手动抓取入口。
  页面刷新仅重新读取数据库，不触发官网采集。
- 数据库不可用时，保留当前页面已经加载的内容并明确提示错误；
  首次加载失败则显示错误与重试入口，不使用内置 JSON 目录兜底。

## 二、后续规划：按官方排期自动抓取

状态：待设计，本轮不实施，未安排发布日期。

### 2.1 用户目标

用户打开产品即可获取后台已核验并保存的节目更新，
无需自己点击同步或前往各视频平台确认是否上线。

### 2.2 已确认方向

- 根据官方公布的节目排期安排自动抓取，临近更新时间提高核验频率。
- 例如动漫 A 周六 11:00 更新，则从周六 10:58 开始进入较高频率的抓取窗口。
  时间示例按北京时间理解；提前两分钟为当前需求示例，
  尚未确定是否作为所有节目的固定规则。
- 新抓取的节目资料、核验结果与处理状态写入 PG，
  页面、周历与观看推荐使用数据库中的一致资料。
- 区分计划更新时间与确认已发布结果，不能仅因排期时间已到，
  就将节目视为已更新。

### 2.3 后续需要设计的内容

抓取频率、窗口持续时间、确认更新后的停止条件、延期与缺失排期处理、
失败退避、平台限流、请求与资源预算，以及现有扫描入口的 PG 存储接入，
均留待此功能启动时进一步确认。

本轮不新增该调度任务，也不把现有扫描算法的固定间隔视为已确认的替代方案。
